
# ADR-002: 圧縮ファイルの遅延展開 移行マイルストーン

ADR-002（圧縮ファイルの遅延展開と2フェーズコンテナAPIの導入）に関する現状の進捗と、今後の完全移行に向けたTODO・マイルストーンです。

## 概要
バックエンド（Rust）での基盤実装と、フロントエンドの主要コンポーネント（`App.tsx`, `LocalFolderContainer`等）でのインターフェース適用は概ね完了しています。
しかし、フロントエンド側のデータフェッチロジックにおいて、依然として全件一括読み込みを行ってしまっているため、UI層でのCPUスパイク解消という本来の目的が達成できていません。

---

## 🚩 Milestone 1: 真の遅延読み込み（チャンク化）の実現
最も重要かつ優先度の高いマイルストーンです。`useImages.ts` が全件一括解決している現状を改め、表示に必要な画像だけを解決するように修正します。

- [ ] **`useImages.ts` の改修**
  - 現状の `container.resolveRange(0, handles.length)` を削除。
  - スクロール位置や現在のインデックス(`initialIndex`等)に基づいて、必要な範囲（例: 前後100件など）だけを `resolveRange` で要求する仕組みに変更。
  - または、コンテナ側（`LocalFolderContainer.ts`）の `listImages()` が持っているチャンク分割取得ロジックを正しく活用するフローに修正する。
- [ ] **UIの非同期読み込み対応**
  - チャンク化によって「まだパスが解決されていない（`diskPath`がない）画像」が発生するため、`ImageViewer` 側で未解決画像のスケルトン表示やオンデマンド解決が正しく機能するか確認・修正する。

## 🚩 Milestone 2: 破壊的変更の完了とクリーンアップ
マイルストーン1が安定稼働した後に実施します。後方互換性のために残されている旧APIや不要なコードを削除し、設計を本来のクリーンな状態に保ちます。

- [ ] **`ImageContainer.ts` の整理**
  - オプションとして残置されている旧 `listImages?(): Promise<ImageSource[]>;` をインターフェースから完全削除する。
- [ ] **`FileSystemService.ts` の整理**
  - `listImagesInContainer` メソッドの定義を完全削除する。
- [ ] **Tauri Adapter の整理**
  - `tauriAdapters.ts` に残っている `listImagesInContainer` の invoke 実装を削除する。
- [ ] **モックとテストコードの整理**
  - `dev/mockService.ts` や `test/mocks.ts`、関連するユニットテストファイルから、上記で削除したメソッドへの参照やモックを削除・修正する。

## 🚩 Milestone 3: パフォーマンス最適化（オプション）
ADR-002の「P3: 先読みは今回スコープ外」として定義されていた部分です。チャンク化導入後の実機での体感パフォーマンスを計測し、必要に応じて着手します。

- [ ] **先読み（Prefetch）の導入検討**
  - `ContainerConfig.prefetchThreshold` 等を活用し、ユーザーが画像の末尾付近に近づいた段階で次のチャンクを裏で解決しておく処理を実装する。
  - ※ ZIPファイルの展開速度などに不満が出た場合のみ対応する。
