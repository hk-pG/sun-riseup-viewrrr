# UI/UX 原則

漫画・イラスト集ビューアとしての体験を、実装 PR で判定するためのチェックリストです。
モック、カラーパレット、コンポーネントカタログはここには書きません。

**状態:** Accepted（プロダクト合意。実装は未着手）  
**日付:** 2026-08-18

## 使い方

UI に触る PR は、この文書との差分を説明すること。迷ったら下の「やらないこと」を先に見る。
判定はデザイナーがいなくてもできる。「表紙以外に目が行くか」「HTML で OS を真似ていないか」「設定軸が増えていないか」の三つで足りる。

GitHub 上の議論は、このファイルを含む PR / 後続 Issue で行う。正本はこのファイルであり、Discussion 単体にはしない。

## 優先順位（衝突したとき）

1. **軸:** OS を問わず、棚とビューアの見た目・操作モデルは一つ。HTML で Aqua や Win32 を模倣しない。
2. **体験の本体:** コンテンツ優先の軽さ。枠より画像と表紙。
3. **macOS / 各 OS:** 見た目ではなく慣習を守る。ネイティブメニュー、ネイティブタイトルバー、修飾キー（`⌘` / `Ctrl`）。

NeeView 的な軽さは、パネルを消すことではなく、常時出す枠を薄くすることと、読む操作をキー・クリック・ホイールに置くことで実現する。

## やること

### 窓

- [ ] メニューとタイトルバーは全 OS でネイティブ。ウィンドウ内に 64px 級の HTML メニューバーを置かない。
- [ ] レイアウトは常時三分割（メニュー枠は OS、左に棚、右に舞台）。兄弟フォルダへすぐ切り替えられること。
- [ ] ショートカットは同じ操作、OS ごとの修飾キー。ビューアの文字キー（`W` / `H` / 矢印など）は OS 共通。
- [ ] 終了は OS の終了コマンドに任せる。`Alt+F4` をメニューに直書きしない。
- [ ] キーバインドの設定 UI は持たない。

### 棚（サイドバー）

- [ ] このアプリは汎用画像ビューアではなく、漫画・イラスト集の閲覧に特化する。識別子は表紙。
- [ ] **出荷既定:** 縦長表紙・1列。表紙はサイドバー幅いっぱい。正方形クロップを中央に置かない。
- [ ] **ユーザー設定は 2×2 のみ:** 形状（縦長 / 正方形）× グリッド（1列 / 2列）。大きさスライダーや列数 3 以上は持たない。
- [ ] 表紙の大きさはサイドバー幅から決める。幅はドラッグで可変し、最後の幅を覚える。幅変更で列数を自動切替しない。
- [ ] 2×2 の操作場所は表示メニューと、棚のコンテキストメニュー。棚先頭に常時の切替ボタンを置かない。
- [ ] **表紙が枠。** 角丸カード、太い選択ボーダー、影、飾りアイコンは描かない。余白は最小。選択は薄い背景差か 1px。フォントは各 OS の UI フォント。
- [ ] Lucide 等のフォルダアイコンは、サムネイルが無いときの仮表示に限る。

### 閲覧（舞台）

- [ ] 画像の周囲は常に暗い舞台（マット）。棚だけがライト / ダークテーマに従う。テーマ切替で舞台を白くしない。
- [ ] 画像上にボタン列のフローティングツールバーを置かない。
- [ ] 出してよいのは薄い HUD のみ（ページ番号など）。位置はビューポートの隅、高透明、短時間。普段は消す。マウス移動とページ送りの直後だけ出す。カーソル直下には出さない。
- [ ] 画像を解析して HUD を逃がさない。内容に応じて位置を変えない。
- [ ] ページ送りはキーボード、ビューア領域の左右クリック、ホイール。ズームは表示メニューと `+` / `-`。
- [ ] **右開き既定。** 左半分クリックと「次へ」が次ページ。左開きは表示メニューで切替。フォルダごとの記憶は持たない。
- [ ] **既定は単ページ。** 見開きは表示メニューのオプション。ウィンドウ幅での自動切替はしない。
- [ ] ホイールはページ送り。拡大中も送りを優先する。`⌘`/`Ctrl`+ホイールのズーム分担は、必要になってから足す。

### 起動と記憶

- [ ] 起動時は前回の親フォルダを復元し、兄弟一覧の棚をすぐ出す。
- [ ] 真の初回（まだ一度も開いていない）だけ、空の棚と暗い舞台。「フォルダを開く」が手がかり。起動のたびにダイアログは出さない。
- [ ] 覚えてよいのは読み方: サイドバー幅、2×2、開き方向、見開きオンオフ。
- [ ] ページ番号・ズームはまだ復元しない。

## やらないこと

- ブランドカラー、ロゴ、イラスト、ガラス質・半透明の OS 模倣マテリアルを「らしさ」のために足すこと。
- shadcn 既定のカード（大きな radius、`border-2`、中央揃えの正方形サムネ、Lucide 付き HTML メニュー）を棚の顔にすること。
- 内容認識 HUD、幅からの見開き自動切替、列数の推定など、「賢く推測する」UI。
- 初日からキー全カスタム、サムネ幅スライダー、列数 1–4 の連続値、起動時フォルダダイアログ強制。
- 見た目を OS ごとに別スキンにすること（本物の OS 枠は除く）。

shadcn/ui は、残る小さな部品（トースト、ツールチップ等）の実装詳細として使ってよい。ただし既定トークンとカード構造を、棚と舞台の見た目にしない。

## 後から足してよいもの（今は持たない）

- ページ位置の復元
- キーバインド設定
- 修飾キー付きホイールズーム
- フォルダごとの開き方向
- 見開き時の奇数ページ（表紙のみ単ページ）などの細則。入れるときは「予測できる、推測しない」を守る
- 舞台の中間グレー（色判定用マット）

## 現状コードとの主な差分（実装時の目印）

合意であり、この文書の追加だけでは直らない。

| 現状 | 原則 |
| --- | --- |
| ウィンドウ内 shadcn Menubar、高さ `h-16` | ネイティブメニュー / タイトルバー |
| ショートカットが `Ctrl+O` / `Alt+F4` 直書き | OS ごとの修飾キー。終了は OS |
| 正方形 100px サムネを中央の角丸カードに載せる | 既定は縦長・1列・幅いっぱい。カード装飾なし |
| サイドバー幅ほぼ固定 | ドラッグ可変、幅を記憶 |
| 画像上に Button 列のフローティングバー | 薄い HUD のみ |
| ビューア背景 `#1a1a1a` と shadcn テーマが混在 | 舞台は常に暗い。棚だけテーマ |
| 起動時に前回フォルダを復元しない | 親フォルダを復元 |

## 変更手順

この原則を変えるときは、実装 PR に混ぜず、このファイルの変更として理由を書く。
設定軸を増やす提案は、既存の 2×2・表示メニューに入るかを先に確認する。入らないなら、原則を更新してから実装する。
